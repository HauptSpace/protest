# `src/auto_cycle.ts` — последовательный запуск шагов

`runCycle(steps, log, timeoutMs)` выполняет шаги по порядку и возвращает
`{ status, steps, duration, reason? }`.

| Шаг вернул | Статус шага | Что дальше |
|---|---|---|
| `true` | `done` | следующий шаг |
| `"skip"` | `skipped` | следующий шаг |
| `false` | `failed` | остановка, `status: "failed"` |
| исключение | `failed` | остановка, `reason` = текст ошибки |
| вышел бюджет `timeoutMs` | `failed` | остановка, остальные шаги остаются `pending` |

Итоговый `status`: `completed` — дошли до конца; `skipped` — **все** шаги пропущены;
`failed` — см. таблицу.

## Что дополнено относительно ТЗ и почему

1. **Когда итог `"skipped"`.** В ТЗ статус есть, а правило — нет. Сделано так: `skipped` —
   если пропущены все шаги (цикл фактически ничего не сделал). Если хотя бы один шаг выполнен —
   `completed`. Пустой список шагов — `completed`.
2. **`timeoutMs` — общий бюджет на весь цикл**, как в ТЗ: если первый шаг занял 600 мс из 1000,
   второму остаётся 400 мс. Шаг, на котором бюджет кончился, — `failed`, следующие — `pending`.
3. **Шаг по таймауту не прерывается.** У `fn` нет `AbortSignal`, поэтому `runCycle` перестаёт
   его ждать, но сам `fn` может продолжить работу в фоне. Если шаг отправляет транзакции —
   учитывайте это (или добавим `signal` в контракт шага).
4. **Синхронное исключение `fn`** (до первого `await`) тоже превращается в `failed`, а не роняет
   `runCycle`.
5. **`steps` в результате — копия**: менять её безопасно.
6. **Тексты `reason`**: `Шаг «x»: <ошибка>`, `Шаг «x» вернул false`,
   `Бюджет N мс исчерпан на шаге «x»`. Таймаут отличается от ошибки шага по типу, а не по тексту.
7. **Логи**: `info` — старт шага, `success` — готово, `warn` — пропуск, `error` — сбой, плюс итог цикла.

## Как встроить в код

```ts
import { runCycle } from './auto_cycle';

const result = await runCycle(
  [
    { name: 'Проверка сети', fn: async () => (await getNetworkConditions(rpc, be)).recommendation === 'go' },
    { name: 'Метаданные', fn: async () => (metadataUri ? 'skip' : ((metadataUri = await uploadTokenMetadata(ipfs, meta)), true)) },
    { name: 'Отправка бандла', fn: async () => { await submitBundleWithRetry(/* … */); return true; } },
  ],
  log,
  120_000,
);
if (result.status === 'failed') notify(result.reason);
```

- **`false` — для «условие не выполнено»** (например, рекомендация сети не `go`), исключение —
  для ошибок. В `reason` будет видна разница.
- **`"skip"` — для идемпотентности**: шаг уже сделан в прошлом цикле (метаданные загружены,
  пул создан) — пропускаем, а не повторяем.
- **Бюджет выбирайте с запасом** по сумме таймаутов шагов: например, `submitBundleWithRetry`
  при 3 попытках может занять до ~94 с.
