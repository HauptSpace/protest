# `src/blockhash_ws.ts` — свежий blockhash через WebSocket

`BlockhashWatcher` подписывается на слоты (`slotSubscribe`) и на каждый новый слот
обновляет blockhash по HTTP RPC. `getCurrent()` мгновенно отдаёт последний известный.

## Что изменено относительно ТЗ и почему

### 1. `getLatestBlockhash` вместо `getBlock(slot)`
`slotSubscribe` присылает слот в момент, когда он только **обработан**, но ещё не подтверждён.
`getBlock` не поддерживает commitment `processed`, и для такого слота почти всегда отвечает
«Block not available for slot». То есть по ТЗ почти каждый слот давал бы ошибку.
`getLatestBlockhash` с commitment `confirmed` — стандартный способ получить свежий blockhash,
и вызывать его можно в любой момент. В поле `slot` записывается слот этого blockhash
(`context.slot`), а не слот из уведомления.

### 2. Не больше одного HTTP-запроса одновременно
Слоты идут примерно раз в 400 мс, ответ RPC может занимать дольше. Если на каждый слот
запускать новый запрос, они будут копиться. Поэтому слоты, пришедшие во время запроса,
схлопываются в **один** повторный запрос после него.

### 3. `current` не откатывается назад
Если поздний ответ принёс blockhash более старого слота, он игнорируется. `update` приходит
только когда слот вырос.

### 4. Собственные слушатели вместо `EventEmitter`
У Node `EventEmitter` событие `error` без подписчика **роняет процесс**. Это противоречит
пункту ТЗ «не падать», поэтому слушатели свои: ошибка без подписчика просто игнорируется,
исключение в обработчике `update` уходит в `error`.

### 5. Сверх ТЗ
- `https → wss`, `http → ws`; query-параметры (например `?api-key=`) сохраняются.
- Backoff сбрасывается до 1 с после подтверждённой подписки, а не после любого `open`.
- `stop()` также отменяет запланированный реконнект и текущий HTTP-запрос.
- Таймаут HTTP-запроса — 10 с.
- Без внешних зависимостей: встроенные в Node 22 `WebSocket` и `fetch`.

## Как встроить в код

```ts
import { BlockhashWatcher } from './blockhash_ws';

// при старте приложения — ОДИН раз
const watcher = new BlockhashWatcher(process.env.RPC_URL!);
watcher.on('error', (err) => logger.warn(err.message));
watcher.start();
// дождаться первого update — сразу после start() getCurrent() === null
// (готовая функция waitForFirstBlockhash — в docs/example.ts)

// где угодно потом
const blockhash = watcher.getCurrent()?.blockhash;

// при остановке приложения
watcher.stop();
```

- **Один watcher на приложение**, а не на каждый бандл: одна WS-подписка дешевле и blockhash
  готов сразу.
- **Подпишитесь на `error`** хотя бы для логов — иначе разрывы будут невидимы.
- **Нагрузка на RPC:** ~2–3 запроса `getLatestBlockhash` в секунду. На бесплатных тарифах
  (Helius/QuickNode free) это заметная доля лимита — учитывайте.
- **Локальный `solana-test-validator`:** WS-порт на единицу больше HTTP (8899 → 8900).
  Watcher берёт тот же порт, что в URL, поэтому для локального валидатора нужен другой URL
  или доработка (отдельный `wsUrl` в конструкторе).
- **Возможная доработка:** `lastValidBlockHeight` приходит в ответе, но отбрасывается — контракт
  `BlockhashInfo` его не содержит. Добавьте, если нужно проверять, не истекла ли транзакция.
