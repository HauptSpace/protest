# `src/trading.ts` — автоматический выход из позиции

`executeExitStrategy(mint, config, wallets, rpcUrl, log, getCurrentPrice, sellTokens)`
исполняет стратегию выхода по токену на всех кошельках и возвращает итог продаж.

| Стратегия | Что делает |
|---|---|
| `manual` | Ничего; сразу пустой результат |
| `target` | Опрос цены каждые 2 с; при `price ≥ targetPrice` — продать всё |
| `trailing` | Опрос каждые 2 с, запоминается пик; при `price ≤ peak × (1 − trailingStopPercent/100)` — продать всё |
| `dca` | По шагам: подождать `time` мс → продать `percent`% **текущего остатка** |

Общий таймаут — 5 минут.

## Что изменено/дополнено относительно ТЗ и почему

### 1. «Продать ALL» = фактический баланс кошелька из RPC
`sellTokens` принимает конкретное количество (`bigint`), «ALL» передать нельзя. Поэтому перед
каждой продажей баланс кошелька по `mint` читается через
`connection.getParsedTokenAccountsByOwner` — для этого и нужен `rpcUrl`. То же для DCA:
«`percent`% остатка» считается от свежего on-chain баланса на момент шага. Кошельки с нулевым
балансом пропускаются без вызова `sellTokens`.

### 2. Итог считается по подтверждённым транзакциям
`sellTokens` возвращает только строку — считаю её **подписью транзакции**. По ней через
`getTransaction` (до 30 с ожидания) берутся:
- `totalSolReceived` — изменение SOL-баланса продавца (`postBalances − preBalances`), то есть
  **чистыми**, уже за вычетом комиссий сети, priority fee и чаевых;
- `totalSold` — фактически списанные токены по `pre/postTokenBalances`.

Если транзакция упала on-chain (`meta.err`), продажа не учитывается и пишется `error`.
Если транзакция не появилась за 30 с — `warn`, в итог не попадает (но могла пройти — проверьте
по подписи из лога).

> **Если ваша `sellTokens` возвращает не подпись**, итог будет пустым. Скажите — переделаю.

### 3. Единицы в `TradingResult`
- `totalSold` — **сырые** единицы токена (без decimals), строкой: `bigint` в `number` не влезает.
- `totalSolReceived` — **лампорты** строкой (1 SOL = 1 000 000 000).
- `avgPrice` — **SOL за 1 целый токен** (с учётом decimals). Чтобы сравнивать с
  `targetPrice`, `getCurrentPrice` должна отдавать цену в тех же единицах.

### 4. Таймаут 5 мин — **ничего не продаётся**, бросается `ExitStrategyTimeoutError`
В ТЗ не сказано, что делать, если цель не достигнута. Варианта два: продать всё по рынку или
оставить позицию. Автоматически продавать по цене, которую стратегия не одобрила, —
рискованно, поэтому выбран **безопасный** вариант: стратегия останавливается, оставшиеся
токены не трогаются, бросается `ExitStrategyTimeoutError`. В `err.partial` лежит то, что
успели продать (для DCA). Если нужно «по таймауту продать всё» — это одна строка, скажите.

### 5. DCA: `time` — задержка от предыдущего шага
«Ждать `time` мс» понято как пауза перед шагом (не как время от старта). Пример:
`[{time: 10000, percent: 50}, {time: 20000, percent: 100}]` — через 10 с продать половину,
ещё через 20 с — остаток. Сумма всех `time` должна быть ≤ 5 мин — проверяется **до** старта,
чтобы не продать половину и упасть по таймауту. Чтобы гарантированно выйти полностью,
последний шаг делайте с `percent: 100`.

### 6. Надёжность (сверх ТЗ)
- Кошельки продаются **параллельно** — на bonding curve цена двигается быстро.
- Ошибка одного кошелька (`slippage`, нехватка SOL на комиссию) логируется и не мешает
  остальным. Повторных попыток нет — оставшиеся токены видны по балансу.
- Ошибка или некорректное значение `getCurrentPrice` (`NaN`, `≤ 0`) → `warn`, опрос продолжается.
- Конфиг проверяется до любых действий: `targetPrice > 0`, `trailingStopPercent ∈ (0, 100)`,
  `percent ∈ (0, 100]`, `time ≥ 0`.

### 7. `Connection` используется, `PublicKey`/`Keypair` — в сигнатурах
Все три импорта из ТЗ задействованы.

## Как встроить в код

```ts
import { executeExitStrategy, ExitStrategyTimeoutError } from './trading';

try {
  const result = await executeExitStrategy(
    mint,
    { exitStrategy: 'trailing', trailingStopPercent: 15 },
    walletKeypairs,
    process.env.RPC_URL!,
    log,
    (mint) => getBondingCurvePrice(connection, mint),        // ваша функция: SOL за 1 токен
    (mint, seller, amount) => sellOnCurve(mint, seller, amount), // ваша: вернуть подпись
  );
  log('success', `Получено ${Number(result.totalSolReceived) / 1e9} SOL, средняя ${result.avgPrice}`);
} catch (err) {
  if (err instanceof ExitStrategyTimeoutError) {
    // цель не достигнута — позиция осталась; решите: ждать дальше или продать вручную
  } else {
    throw err;
  }
}
```

- **`sellTokens` должна дождаться отправки** и вернуть подпись. Подтверждение ждёт уже этот модуль.
  Слиппедж задавайте внутри `sellTokens` — при обвале цены без него продажа может пройти по
  очень плохой цене.
- **`getCurrentPrice`** — читайте состояние bonding curve напрямую из аккаунта через RPC, а не
  через внешний API: так быстрее и без rate-limit. Опрос раз в 2 с — это 150 запросов за 5 мин.
- **Запуск после покупки:** вызывайте сразу после подтверждения покупки, в фоне (не блокируя
  основной поток). Для параллельных позиций — отдельный вызов на каждый `mint`.
- **Не вызывайте дважды для одного `mint`** — две стратегии будут продавать одни и те же токены
  наперегонки.
- **Ручная остановка** сейчас не предусмотрена (нет `AbortSignal` в контракте). Если нужна
  кнопка «стоп» — добавлю необязательный параметр `signal`.
