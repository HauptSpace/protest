# `src/raydium.ts` — создание пула ликвидности SOL/токен на Raydium

`createLiquidityPool(mint, config, payer, rpcUrl, log)` создаёт пул, вносит стартовую
ликвидность и, если `lockLp`, **навсегда** блокирует её. Возвращает адрес пула,
`lpLocked` и подпись транзакции создания.

| `poolType` | Программа Raydium | Транзакции |
|---|---|---|
| `amm` | **CPMM** (`CPMMoo8L3F4NbTegBCKVNunggL7H1ZpdTHKxQB5qKP1C`) | 1. создание пула + ликвидность · 2. блокировка LP |
| `clmm` | CLMM (`CAMMCzo5YL8w4VFF8KVHrK22GGUsp5VTaW7grrKgrWqK`) | 1. создание пула · 2. позиция на весь диапазон · 3. блокировка позиции |

Блокировка — Raydium Burn & Earn (`LockrWmn6K5twhz3y9w1dQERbmgSaRkfnTeTKbpofwE`).
Работает на **mainnet и devnet** — сеть определяется автоматически по RPC.

## Что изменено относительно ТЗ и почему (всё согласовано с вами)

### 1. `amm` = Raydium CPMM, а не AMM V4
Пул на AMM V4 (`675kPX…`) сначала требует создать **рынок OpenBook**: отдельный набор
аккаунтов с рентой порядка 0.4–3 SOL. CPMM — тот же constant-product пул (x·y=k), но без
OpenBook: дешевле, и у него есть встроенная блокировка LP. Сейчас это рекомендованный Raydium
тип для новых пулов.

### 2. Официальный SDK v2, а не ручные инструкции
Добавлена зависимость `@raydium-io/raydium-sdk-v2` (версия зафиксирована: `0.2.74-alpha`).
Раскладку аккаунтов в инструкциях Raydium (по ~20 аккаунтов) нельзя проверить без сети, а
ошибка в ней — это упавшая транзакция или потерянная рента. SDK — официальный источник этих
раскладок. Program ID — настоящие, из SDK, а не заглушки.

### 3. Новое поле `initialLiquidityTokens: bigint` — обязательно
В конфиге было только `initialLiquiditySol`. Стартовая цена = SOL / токены, поэтому
количество токенов нужно задать явно, в минимальных единицах (raw, без decimals).
Без него функция бросает ошибку до любых запросов.

### 4. Блокировка **бессрочная**, `lockPeriodDays` не используется
Raydium Burn & Earn блокирует ликвидность **навсегда**: вывести её нельзя никогда, можно
только забирать комиссии торговли (через NFT, который получает `payer`). Срочной блокировки
у Raydium нет. Если `lockPeriodDays > 0`, в лог пишется `warn`.

### 5. Таймаут 30 с — на **каждую** транзакцию
Если бы 30 с были общими на 2–3 транзакции, таймаут мог бы оборвать процесс посередине: пул
уже создан, а ликвидность не внесена или не заблокирована. При таймауте ошибка содержит
подпись: **транзакция ещё может пройти** — проверьте её в обозревателе, прежде чем повторять.

### 6. Частичный успех — `RaydiumPartialError`
Если пул создан, а следующий шаг упал (ликвидность CLMM или блокировка), бросается
`RaydiumPartialError`. В `err.partial` лежат адрес пула и подпись: пул **уже существует
on-chain**, и повторный вызов создаст ещё один. Дальше действуйте по этому адресу.

### 7. Проверки до отправки (сверх ТЗ)
- `mint` — действительно mint-аккаунт; программа токена (Token / Token-2022) и decimals
  берутся из него же.
- Хватает токенов и SOL (для CPMM — плюс комиссия создания пула из конфига Raydium).
  Рента аккаунтов и комиссии сети сверху не считаются точно — их ловит preflight-симуляция,
  которая ничего не стоит.
- Каждая транзакция отправляется с preflight-симуляцией: ошибка ловится **до** попадания в
  блок.

### 8. Выбор комиссии пула
Берётся конфиг Raydium с торговой комиссией **0.25 %**, если он есть, иначе конфиг с
наименьшим индексом. Константа `PREFERRED_TRADE_FEE_RATE`.

### 9. CLMM: позиция на весь диапазон цен
Ликвидность CLMM вносится позицией от минимального до максимального тика — по поведению
это аналог обычного пула. Количество токенов фиксировано, по SOL заложен запас **+1 %** на
округление цены в тиках (будет списано не больше).

## Изменения в зависимостях

- **Добавлены:** `@raydium-io/raydium-sdk-v2` (0.2.74-alpha, фиксированная), `bn.js`,
  `decimal.js` — их требует API SDK; `@types/bn.js` (dev).
- **`@solana/web3.js` обновлён до ^1.99.0** — версии, которую использует SDK. Иначе в проекте
  были бы две копии web3.js, и проверки `instanceof PublicKey` внутри SDK могли бы не сработать
  на наших ключах.
- `jito-ts` жёстко требует web3.js `~1.77.3` и держит свою копию. Проверено, что
  `jitoBundle.ts` работает с транзакциями из новой версии (сборка бандла с tip-транзакцией).
- SDK тяжёлый: около 230 МБ в `node_modules`.

## Как встроить в код

```ts
import { createLiquidityPool, RaydiumPartialError } from './raydium';

try {
  const pool = await createLiquidityPool(
    mint,
    {
      poolType: 'amm',
      initialLiquiditySol: 10,
      initialLiquidityTokens: 800_000_000n * 10n ** 6n,   // 800M токенов при decimals = 6
      lockLp: true,
      lockPeriodDays: 0,
    },
    payerKeypair,
    process.env.RPC_URL!,
    log,
  );
  log('success', `Пул: https://raydium.io/swap/?inputMint=sol&outputMint=${mint.toBase58()}`);
} catch (err) {
  if (err instanceof RaydiumPartialError) {
    // пул уже есть: err.partial.poolAddress — НЕ вызывайте createLiquidityPool повторно
  }
  throw err;
}
```

- **Сначала devnet.** Укажите devnet-RPC — модуль сам переключится на devnet-программы Raydium.
  Прогоните полный цикл (создание → ликвидность → блокировка) на тестовом токене, потом mainnet.
- **Блокировка необратима.** `lockLp: true` — ликвидность заблокирована навсегда. Это и есть
  смысл блокировки для покупателей, но для своих тестов на mainnet ставьте `false`.
- **`payer` должен владеть токенами** — они берутся с его кошелька. SOL оборачивается в WSOL
  автоматически.
- **Сколько SOL держать:** `initialLiquiditySol` + комиссия создания пула (CPMM ~0.15 SOL на
  mainnet, точное значение приходит из API Raydium) + рента аккаунтов и комиссии сети.
  Держите запас ~0.3 SOL сверху.
- **Не вызывайте повторно после ошибки, не проверив**, создан ли пул: для одной пары и одного
  конфига комиссий CPMM-пул может быть только один, повтор упадёт; CLMM — тоже по конфигу.
- **Сеть к API Raydium:** SDK берёт конфиги комиссий с `api-v3.raydium.io` — сервер должен иметь
  к нему доступ.
